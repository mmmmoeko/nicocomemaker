# ニコメメーカー 仕様書 (v2.2)

既存の動画にニコニコ動画風のコメントを重ねた動画を作るツール。

## 1. 確定した方針

| 項目 | 決定 |
|---|---|
| 実行形態 | **2 つ**。ローカル版(Node + ffmpeg)と、サーバー不要のブラウザ版(§13) |
| 出力 | ブラウザでのリアルタイムプレビュー + mp4 焼き込みの両方 |
| コメント入力 | Google スプレッドシートで作成 → CSV をダウンロードして D&D。**取り込み後はアプリ上で編集** |
| 時刻 | 行ごとに「手で固定」か「自動配置」を選べる。**時刻を書かなければ自動**(§3.5) |
| 再現度 | 見た目重視のシンプル版。ただし寸法・色はニコ動の実測値を既定値として採用し、すべて設定で変更可能 |
| 焼き込み方式 | プレビューと同じ Canvas 描画コードでコメント層を生成し ffmpeg の overlay へ |
| 入力動画 | mp4 / mov。ブラウザが再生できない形式はプレビュー用プロキシを自動生成 |
| 想定尺 | 数分 |
| 書き出しモード | ①合成 mp4 ②**コメント層のみ(アルファ付き)** の 2 種 |
| フォント | Noto Sans JP を同梱(ライセンス OFL 1.1)。システムフォントにも切替可 |

---

## 2. ニコニコ動画の実際の描画パラメータ

本家 HTML5 プレイヤー互換の描画ライブラリ [niconicomments](https://github.com/xpadev-net/niconicomments) の実装値。
**これらを既定値とし、UI からすべて変更できるようにする。**

### 2.1 座標系

| 項目 | 値 |
|---|---|
| 基準ステージ | 512 × 384(16:9 フル幅時は 683 × 384) |
| 実描画キャンバス | 1920 × 1080 |
| スケール | 1920 / 683 ≒ 2.811 |

コメントの寸法はすべて **384 高の基準座標系**で定義され、最後に一括でスケールされる。
本アプリも同じ方式にする(=動画の解像度が変わっても見た目の比率が変わらない)。

### 2.2 フォントサイズ(基準座標系 384 高での px)

| size | px | 1画面に入る行数 |
|---|---|---|
| `small` | 18 | 21 行 |
| `medium` | 27 | **13.1 行** |
| `big` | 39 | 8.4 行 |

※ 行数は本家の値そのまま。`medium` で 13.1 行 = 行高 384/13.1 ≒ 29.3px。

### 2.3 フォントファミリー(OS 別・本家準拠)

| プラットフォーム | 既定フォント | weight |
|---|---|---|
| macOS (10.11+) | `"ヒラギノ角ゴ ProN W6", HiraKakuProN-W6, "Hiragino Kaku Gothic ProN"` | 600 |
| Windows | `Arial, "ＭＳ Ｐゴシック", "MS PGothic", MSPGothic` | 600 |

コマンドで切り替わるフォント(HTML5 プレイヤーで追加されたもの):

| コマンド | フォント | weight |
|---|---|---|
| `defont`(既定) | 上記 OS 別フォント | 600 |
| `gothic` | `"游ゴシック体", "Yu Gothic", YuGothic` | 400 |
| `mincho` | `"游明朝体", "Yu Mincho", YuMincho` | 400 |

### 2.3.1 本アプリのフォント方針(同梱する)

環境によって見た目が変わるのを避けるため、**フォントを同梱する**。

| | 内容 |
|---|---|
| 同梱フォント | **Noto Sans JP**(可変フォント / weight 100〜900) |
| ライセンス | SIL Open Font License 1.1 — 再配布可。`web/fonts/OFL.txt` に全文を同梱する |
| ファイル | `web/fonts/NotoSansJP.ttf`(可変版 1 ファイル、約 9MB) |
| 既定の weight | **600**(ニコ動の macOS 既定と同じ) |
| 読み込み | `@font-face` でローカル配信。ネットワークアクセスは一切しない |

- 同梱フォントは Canvas 描画にのみ使う。**書き出し時もブラウザ側で描くので、ffmpeg 側にフォント設定は不要**
- 設定でシステムフォント(ヒラギノ角ゴ ProN W6 など)にも切り替えられる
- 起動時に `document.fonts.ready` を待ってから初回描画する(未ロード状態で描くと別フォントで焼き込まれるため)

`gothic` / `mincho` 相当のコマンド切り替えは MVP では入れず、UI のフォント設定で任意指定できるようにする。

### 2.4 縁取り

| 項目 | 値 |
|---|---|
| 線幅 | 2.8px(基準座標系) |
| 色 | `#000000` |
| 文字色が `#000000` のときだけ | `#FFFFFF`(反転) |
| **不透明度** | **0.4** |

縁取りは不透明の黒ベタではなく **40% の半透明**。ここが「それっぽさ」に効くので必ず守る。
描画順は `strokeText` → `fillText`。

### 2.5 表示時間

| 項目 | 値 |
|---|---|
| 既定の表示時間 | **3.0 秒**(本家 vpos 300) |
| 流れるコメントの横断 | 画面外の助走を含めて実質 約 4 秒 |

本家では `@5` のようなコマンドで表示時間を個別に変えられる。本アプリでは全体設定として持ち、MVP では個別指定を入れない。

### 2.6 コメント同士の間隔

| 項目 | 値 |
|---|---|
| コメント間の横の余白 | 5px(1920 幅換算) |

本家は「画面の左右端ではなく、内側に寄せた範囲」で衝突を見ているが、
本アプリは §4.1 の**速度差まで含めた厳密な判定**を使うので、この近似は要らなくなった。

## 3. データモデル

### 3.1 コメント 1 件

```
Comment {
  id:    string   // アプリ内部の一意 ID
  seq:   number   // リスト上の並び順(取り込み順)。自動配置はこの順に使う
  auto:  boolean  // true なら time は自動で決まる(§3.5)
  time:  number   // 秒。表示開始時刻。auto でも必ず実数が入っている
  text:  string   // 本文
  color: string   // 既定 "white"
  pos:   "naka" | "ue" | "shita"    // 既定 "naka"
  size:  "small" | "medium" | "big" // 既定 "medium"
}
```

`auto` の行でも `time` には必ず実数が入る。これが設計の要で、
**レンダラもレイアウトも書き出しも「自動かどうか」を一切気にしない**。
自動配置は「いつ time を計算し直すか」という問題に閉じている。

### 3.2 CSV スキーマ

1 行目はヘッダー。列の順番は問わず、**ヘッダー名で対応付ける**。

| 列名 | 必須 | 内容 |
|---|---|---|
| `time` | | 表示開始時刻。**空なら自動配置**(§3.5) |
| `text` | ○ | コメント本文 |
| `color` | | 色 |
| `pos` | | 表示位置 |
| `size` | | 文字サイズ |

- ヘッダー名は日本語も受理: `時刻` `コメント` `色` `位置` `サイズ`
- ヘッダー行が無ければ「1列目=time, 2列目=text」として扱う
- ただし**ヘッダーも時刻も無い場合は「本文だけを並べた一覧」**とみなし、全行を自動配置にする
  ```
  うぽつ
  wwwww
  ここすき
  ```

#### 区切り文字は文章ごとに見分ける

本文にカンマが入ることは珍しくない(`+10,000!?` `1,000円かよ`)。
カンマを無条件に列の区切りにすると、こうした本文が壊れる。
そこで**文章全体を見て区切りを 1 つに決める**。

| 見分け | 区切り | 理由 |
|---|---|---|
| どこかの行にタブがある | タブのみ | スプレッドシートからのコピー。カンマは本文 |
| 1 行目に既知の列名がある | カンマ | ふつうの CSV |
| カンマを含む行の 8 割以上で、1 列目が時刻として読める | カンマ | 「時刻,本文」の並び |
| どれでもない | **なし** | 本文だけの一覧。カンマも引用符も本文の一部 |

さらに、**`text` が最後の列のときに限り**、余ったセルは本文に戻す。
`time,text` の見出しで `0:03,+10,000!?` と書いても本文は `+10,000!?` になる。
- 空行は無視(`#` 始まりの行は本文として扱う。`#tvtokyo` のようなコメントがあるため)
- 不正な行はスキップし、UI に行番号付きで一覧表示する

**time の書式**(自動判別)

- `12` `12.5` — 秒
- `1:23` `1:23.5` — 分:秒
- `0:01:23` — 時:分:秒

**color** — ニコ動の色名 / 日本語色名 / `#RRGGBB`

| コマンド | 日本語 | 値 |
|---|---|---|
| `white` | 白 | `#FFFFFF` |
| `red` | 赤 | `#FF0000` |
| `pink` | 桃 | `#FF8080` |
| `orange` | 橙 | `#FFC000` |
| `yellow` | 黄 | `#FFFF00` |
| `green` | 緑 | `#00FF00` |
| `cyan` | 水 | `#00FFFF` |
| `blue` | 青 | `#0000FF` |
| `purple` | 紫 | `#C000FF` |
| `black` | 黒 | `#000000` |

**pos** — `naka`(既定) / `ue` / `shita`。`中` `上` `下` も可
**size** — `medium`(既定) / `big` / `small`。`中` `大` `小` も可

### 3.3 想定するスプレッドシート

```
time    text                  color   pos     size
0:03    うぽつ
0:05    wwwwwwww
0:08    ここすき                 red
0:12    ここから本編              yellow  ue      big
```

### 3.4 CSV は往復させる

CSV は取り込み専用にしない。アプリ上で編集した結果を**同じスキーマの CSV としてエクスポート**でき、スプレッドシートに貼り戻せる。

書き出す時刻は 1ms まで保持する(`0:05.125` のような形)ので、
読み込み → 編集 → 書き出し → 読み込み を繰り返しても値がずれない。
1 時間を超える場合は `1:01:01.5` のように時を付ける。

### 3.5 時刻の自動配置

時刻を書かずに本文だけ並べ、アプリ側で散らしてもらうためのしくみ。

#### 考え方

「時刻を持たないコメント」という別種のデータは作らない。
**行ごとの `auto` フラグを見て `time` を計算で埋める**だけにする。

```
コメント変更 / 設定変更 / 動画差し替え
        ↓
  applyAutoTimes()   ← auto の行だけ seq 順に time を振り直す
        ↓
  並べ替え → relayout() → redraw()
```

#### 配置の計算(`web/autotime.js`)

区間 `[start, end]`(既定は動画全体)に `n` 件を置く。

| モード | 間隔 |
|---|---|
| `spread`(既定) | `spacing = (end - start) / n` — 件数を区間全体に散らす |
| `rate` | `spacing = 1 / 毎秒の件数` — 先頭から詰める。区間を超えた分は警告を出す |

区間の終わり `end` は 3 通りから選ぶ(`auto.endMode`)。

| 値 | 終わり | 用途 |
|---|---|---|
| `video`(既定) | 動画の最後 | 最後のコメントは流れ切る前に動画が終わる(本家と同じ) |
| `fit` | `尺 − 横断秒数` | **最後のコメントまで見切れさせない** |
| `custom` | 指定した時刻 | 途中で切り上げる |

`fit` は横断秒数から逆算するので、「流れる速さ」を変えると終端も自動で追従する。

```
t_i = start + (i + 0.5) * spacing + (seededUnit(id) - 0.5) * spacing * ゆらぎ
```

- **ゆらぎはコメント ID から決定的に作る**。乱数だと再計算のたびに全部が飛び跳ねて
  プレビューが安定しない。レイアウトの重なり回避と同じ手を使う
- ゆらぎを入れたあと**時刻を昇順に並べ直して seq 順に割り当てる**。
  こうすると「リストの上から順」を保ったまま、間隔だけが不揃いになる
- リストが動画より短くても**複製はしない**。単に薄く散る

#### 手で固定したものと混ぜる

- 時刻セルに値を入れると、**その行だけ `auto` が外れて固定**になる
- 時刻セルを空にすると**自動に戻る**(CSV の空欄と同じ意味)
- 自動の行は一覧で時刻を斜体グレーで表示する

#### 一括操作

| ボタン | 動作 |
|---|---|
| 時刻を確定 | 自動の行をすべて、その時点の時刻で固定する |
| 全部を自動に | すべての行を自動配置に戻す |

「時刻を確定」を押した後の状態は、最初から手で時刻を書いたものと完全に同じ。
全体の流れを自動で決めてから細部を詰める、という進め方ができる。

#### CSV の往復

- **読み**: `time` が空 → その行は `auto`
- **書き**: `auto` の行は `time` を空で書き出す(読み直しても自動のまま)
- 設定の「CSV書出で時刻を確定する」を入れると、実際の時刻を書き込んで固定できる

#### 密度の表示

配置の結果として **毎秒の件数**と**画面上の常時の個数**を UI に出す。
コメントは `scrollDuration` 秒かけて横断するので、

```
画面上の同時表示数 ≒ 毎秒の件数 × 流れる秒数
```

20 秒に 50 件 → 毎秒 2.5 → 常時およそ 10 個。

| 毎秒 | 20秒での総数 | 画面上 | 印象 |
|---|---|---|---|
| 1 | 20 | 約4 | 途切れないが寂しい |
| 2〜3 | 40〜60 | 8〜11 | ほどよい |
| 5 | 100 | 約19 | かなり密 |
| 10 | 200 | 上限40に当たる | 弾幕 |

## 4. 描画仕様(シンプル版)

すべて §2 の基準座標系(高さ 384)で計算し、最後に `動画の高さ / 384` 倍する。

### 4.1 naka(流れるコメント)

- 右外から現れ、左外へ等速で移動。横断時間は設定値(既定 4.0 秒)
- 移動距離 = `画面幅 + テキスト幅`

#### 行の空き判定(重要)

移動距離が `画面幅 + 自分の幅` なので、**長いコメントほど速い**。
そのため、先に入った短いコメントに、後から来た長いコメントが追いつく。
「前のコメントが右端を抜けたか」だけを見ていると、この追突を防げない。

同じ行に入れてよい条件は 2 つあり、両方を満たす必要がある。

| | 条件 |
|---|---|
| (a) | 入った瞬間に、先客の右端を踏まない |
| (b) | 先客が画面から出きるまでに、追いついて追い越さない |

どちらも「先客が入ってから何秒あければよいか」に直せる。
`D` = 横断秒数、`baseW` = ステージ幅、`pad` = コメント間の余白、
`w_先` `w_新` をそれぞれの幅として、

```
必要な間隔 = D × max( (w_先 + pad) / (baseW + w_先),
                      (w_新 + pad) / (baseW + w_新) )
```

(a) は先客の幅、(b) は**新しく入るコメントの幅**で決まる。
つまり空きかどうかは行だけでは決まらず、**入れようとしているコメントによって変わる**。

#### 行が足りないとき

上から順に空いている行を探し、どこにも入らなければ重ねるしかない。
このとき**ランダムな位置に置くと先客の真上に乗って、どちらも最後まで読めなくなる**。

そこで「重なる高さ × 重なっている残り時間」が最小になる位置を選ぶ(`leastBadSlot`)。
重なりは避けられなくても、短く・浅く済む。

#### 実測

3分相当・1920×1080・medium で、重なった面積が画面に占める割合。

| 密度 | 改善前(ランダム) | 改善後 |
|---|---|---|
| 毎秒 2 件(画面に約 8 個) | 平均 0.2% / 20 件が重なる | **0%** |
| 毎秒 5 件(画面に約 20 個) | 平均 0.46% / 46 件が重なる | **0%** |
| 毎秒 10 件(画面に約 40 個) | 平均 7.69% / 228 件が重なる | **0.01% / 10 件** |

同時表示の上限(既定 40)がそのまま行数の限界に効くので、
既定のままなら実用上ほぼ重ならない。上限を 120 まで上げると、
13 行しかない画面に 120 個を詰めることになり、当然重なる。

### 4.2 ue / shita(固定コメント)

- 水平中央に静止。表示時間は設定値(既定 3.0 秒)
- `ue` は上から、`shita` は下から順に空きレーンへ積む
- 空きが無ければ最上段/最下段に重ねる

### 4.3 制限

- 同時表示数の上限 **40**(設定可)。超過分は表示しない
- 1 コメントの最大文字数 **75**(超過分は切り捨て)

### 4.4 文字の縦位置

和文フォントの字面(ascent + descent)は em ボックスより大きいため、行高だけを頼りに置くと
画面の上端・下端で文字が切れる。`measureText().fontBoundingBoxAscent/Descent` で実際の字面を測り、

- 字面を行の中で縦中央に置く
- コメント全体の字面が画面からはみ出す分だけ内側へ寄せる

としている。行どうしの字面が多少重なるのは本家も同じなので、そこは許容する。

### 4.5 状態を持たない設計

renderer は「時刻 t とコメント配列 → その瞬間の画」を返す純粋な関数にする。
レーン割り当ては**動画読み込み時/コメント変更時に一括で事前計算**し、`Comment` に `lane` を持たせる。
これによりシークしても常に正しい画が出て、プレビューと書き出しが完全に一致する。

## 6. 入力動画の扱い(mov 対応)

mov は **中身のコーデック次第でブラウザが再生できない**(ProRes、一部の HEVC など)。
プレビューがブラウザの `<video>` 頼みなので、ここを吸収する。

1. ファイルを受け取ったらサーバーで `ffprobe` し、解像度 / fps / 尺 / 映像コーデック / 音声コーデックを取得
2. **H.264 or VP9 or AV1 + AAC/Opus** なら、そのまま `<video>` に渡す
3. そうでなければ **プレビュー用プロキシ**を生成する
   - `ffmpeg -i input.mov -c:v libx264 -preset veryfast -crf 28 -vf scale=-2:720 -c:a aac proxy.mp4`
   - 数分の動画なら十数秒〜1分程度。進捗を出す
   - プレビューはプロキシ、**書き出しは必ず元ファイル**を使う
4. 判定不能・変換失敗時はその旨を UI に出す

### 7.0 設計方針

**README を読まずに使えること**を基準にする。具体的には、

- 次に何をすればいいかが常に画面上にある(3ステップの案内)
- 隠しコマンドを作らない。挙動はすべて押せるものとして見えている
- 設定は意味のある言葉で出す。生の数値は詳細設定に隠す

### 7.1 コメントを入れる

3 通りを同じ場所に並べる。中心は**貼り付け**。

| 入口 | 用途 |
|---|---|
| **貼り付け** | スプレッドシートからコピーしてそのまま貼る。**貼った瞬間に取り込む** |
| CSV読込 | ファイルから読む |
| ＋ 追加 | 1 件ずつ書く |

コメントが 0 件のときは、一覧の場所に貼り付け欄を大きく出す。
1 件以上あるときは `貼り付け` ボタンで同じ欄を開く(「今のコメントに追加する」を選べる)。

貼り付けたテキストは CSV パーサをそのまま通す。スプレッドシートのコピーはタブ区切りなので、
特別扱いなしで列ごと貼れる。本文だけの 1 列でも成立する(§3.2)。

### 7.2 コメントを編集する

- 一覧の行はその場で編集できる。行をクリックするとその時刻にシーク
- 行頭のチェックボックスで選択。Shift + クリックで範囲選択
- 時刻の左の **［自動］/［固定］バッジ**を押すと切り替わる。時刻を書けば固定、空にすれば自動
- Undo / Redo(Cmd+Z / Cmd+Shift+Z)
- 状態は localStorage に自動保存

#### まとめて削除

| 操作 | 内容 |
|---|---|
| ヘッダーのチェックボックス | 全選択 / 全解除(一部選択中は中間状態を表示) |
| `Cmd+A` | 全選択 |
| `Esc` | 選択を解除 |
| `Delete` / `Backspace` | 選択した行を削除 |
| 全削除 | **2 段階**。1 回目で「もう一度で全削除」に変わり、3 秒以内の 2 回目で実行 |

全削除に確認ダイアログは出さない。モーダルは邪魔なので、ボタン自身が 2 段階になる方式にした。

### 7.3 時刻バー

コメント一覧の直下。時刻の話はコメントの話なので、設定パネルではなくここに置く。

```
時刻 [自動で散らす|手で指定]  [区間全体に散らす▾] ゆらぎ ──●── 区間 [0:00]〜[見切れないところまで▾] [時刻を確定]
自動 50 件 — 毎秒 2.50 件 · 画面に常時 約 10.0 個 · 最後は 2:56
```

**密度を数字で返す**のが要点。件数を入れると「毎秒何件・画面に何個」が即座に出るので、
どれくらい入れればいいかを README で調べる必要がない。

### 7.4 設定パネル

生の数値をそのまま並べると意味が読み取れないので、2 層にする。

**通常** — スライダーと言葉

| 項目 | 中身 |
|---|---|
| 文字の大きさ | `fontScale`。フォントサイズを k 倍、行数を 1/k にして**まとめて**動かす |
| 文字の太さ | `fontWeight` |
| フォント | 同梱 / システム |
| 縁取りの濃さ | `strokeOpacity` を % で表示 |
| 流れる速さ | `scrollDuration` を**左右反転**して表示(右がはやい) |
| 上下固定の表示時間 | `fixedDuration` |
| 画面に出す最大数 | `maxActive` |

**詳細設定**(折りたたみ) — §2 のニコ動準拠の生の数値
フォントサイズ小中大、1画面の行数小中大、縁取りの線幅、最大文字数、当たり判定の右端。

`fontScale` を入れたことで、通常の操作では**フォントサイズと行数の二重露出が消える**。
両方をいじりたい場合だけ詳細設定を開く。

### 7.5 キー操作

再生バーの `キー操作` ボタンで一覧を出す。ショートカットを画面から辿れるようにするため。

- `video.requestVideoFrameCallback()` で映像フレームに同期(非対応環境は `requestAnimationFrame`)
- 描画の基準時刻は常に `video.currentTime`

## 9. 書き出しの仕組み

コメント層は**常に透過 Canvas として生成**する。それをどう扱うかだけがモードの差。

```
ブラウザ                              サーバー              ffmpeg
─────────                            ─────────            ────────
for f in 0..totalFrames:
  renderer.draw(canvas, f/fps)       ← プレビューと同一コード
  getImageData()
  encodeFrame()  ← 透明ランを圧縮
                     ──HTTP POST──>  decodeFrame() ──> stdin (rawvideo rgba)
```

- fps・解像度は元動画に合わせる
- 中断ボタンで ffmpeg を kill し、書きかけのファイルを消す
- 書き出し開始時にコメントと設定を固定するので、途中で編集しても出力は混ざらない

### 9.1 フレームの受け渡し(重要)

当初は各コマを **PNG** にして ffmpeg へ渡す設計だったが、実測で
**`OffscreenCanvas.convertToBlob({type:'image/png'})` が 1 コマあたり約 1014ms** かかった
(描画自体は 0.01ms)。12 秒の動画で 5 分を要し、実用にならない。

そこで **PNG をやめ、生の RGBA を独自の軽量圧縮にかけて送る**。

コメント層は画素のほとんどが完全透明(RGBA すべて 0)なので、
「透明が何画素続くか + 実データ何画素 + その中身」の繰り返しで表す(`web/rle.js` / `server/rle.js`)。

| 方式 | 1コマあたり | 12秒/720p の書き出し |
|---|---|---|
| PNG (`convertToBlob`) | 1014 ms | 約 305 秒 |
| 生 RGBA をそのまま送る | 約 207 ms(転送律速) | 約 65 秒 |
| **生 RGBA + 透明ラン圧縮** | **約 15 ms** | **約 6 秒** |

実測でおおむね 1/50 に縮む。ffmpeg 側は `-f rawvideo -pixel_format rgba` で受ける。

- 1 リクエストは 8MB または 60 コマまで
- 送信中に次のコマを描く(先行 1 本、順番は保つ)

### 9.2 モードA: 合成 mp4(既定)

元動画をブラウザでシークし直す必要がないので速く、元映像も余計に触らない。

```
ffmpeg -i input.mov \
       -f rawvideo -pixel_format rgba -video_size WxH -framerate <fps> -i pipe:0 \
       -filter_complex "[0:v][1:v]overlay=format=auto:eof_action=pass" \
       -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p \
       -c:a copy | -c:a aac -b:a 192k | -an \
       -movflags +faststart output.mp4
```

音声は元が AAC ならコピー、そうでなければ AAC に変換。音声が無ければ `-an`。

### 9.3 モードB: コメント層のみ(アルファ付き)

元動画を一切入力せず、コメント層だけをアルファチャンネル付きで書き出す。
Premiere / After Effects / Final Cut / DaVinci に持ち込んで、向こうで重ねるための出力。

| 形式 | ffmpeg | 特徴 |
|---|---|---|
| **MOV(既定)** | `-c:v qtrle -pix_fmt argb` | 可逆。透明部分が多いので RLE がよく効き**軽い** |
| MOV | `-c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le` | 業務標準。同条件で qtrle の約 4 倍のサイズ |
| 連番 PNG | `-c:v png` → `%06d.png` | どこでも読める最終手段 |

- **音声は含めない**
- 解像度・fps・尺は読み込んである動画に合わせる(動画の読み込みは必須)
- 背景は完全透明。「透過表示」ボタンでチェッカーボード背景に切り替えて確認できる

### 9.4 保存先とファイル名

**`output/` に直接書き出す**(§11 の比較による)。`NICOCOME_OUTPUT` 環境変数で変更可能。

ファイル名は**タイムスタンプ付き**。上書き確認を出さず、常に新しいファイルを作る。

```
<元動画のファイル名>_<YYYYMMDD-HHMMSS>.mp4          モードA
<元動画のファイル名>_comments_<YYYYMMDD-HHMMSS>.mov  モードB
```

完了後に「Finder で表示」ボタンを出す。

## 11. 決定の根拠: 書き出し先

| | `output/` に直接書く | ブラウザにダウンロードさせる |
|---|---|---|
| ファイルの流れ | ffmpeg → 最終ファイル | ffmpeg → 一時ファイル → HTTP → ダウンロードフォルダ |
| 数分の動画(数百MB) | 追加コストなし | **もう一度全部書き直すので時間とディスクを二重に消費** |
| 保存先の選択 | 設定で固定(変更可) | 毎回 OS のダイアログで選べる |
| 完了後の導線 | 「Finder で表示」でそのまま開ける | ダウンロードフォルダから探して移動する手間 |
| 何度も試すとき | 上書き or 連番で溜まる | ダウンロードフォルダが `output (3).mp4` で荒れる |

ローカル専用ツールでサーバーとブラウザが同じマシンにいるので、**わざわざ HTTP を往復させる理由がない**。`output/` 直書きを採用する。

## 12. 決定の記録

### 実装中に判明して方針を変えたもの
- **フレームの受け渡しを PNG から生 RGBA + 透明ラン圧縮に変更**(§9.1)。
  PNG エンコードが 1 コマ 1014ms かかり実用にならなかったため。結果として約 50 倍速くなった。
- **文字の縦位置を字面ベースに変更**(§4.4)。行高だけで置くと画面の上下で文字が切れたため。

### あとから足したもの
- **区切り文字の自動判別**(§3.2)。カンマとタブを常に両方区切りにしていたため、
  `+10,000!?` のような本文が列に割れて取り込めなかった。スプレッドシートからの
  コピー(タブ区切り)でも壊れていた。あわせて `#` 始まりをコメント行とする仕様を廃止した
  (`#tvtokyo` のような本文を黙って捨てていたため)。
- **厳密な衝突回避**(§4.1)。当初は「前のコメントが右端を抜けたか」だけを見る簡易版にしていたが、
  長いコメントほど速いという性質のせいで追突が起き、密度を上げると画面が読めなくなった。
  速度差まで含めた条件に差し替え、行が尽きたときの置き場所も最適化した。
- **UI の全面整理**(§7)。「README を読まずに使えること」を基準に、貼り付け入力を第一の入口にし、
  隠し機能(時刻セルを空にすると自動に戻る)をバッジに置き換え、設定を言葉とスライダーにした。
- **区間の終わりを 3 モードに**(§3.5)。既定のままだと最後のコメントが流れ切る前に動画が終わるため。
- **選択削除と全削除**(§7.1)。行のクリックは既にシークに使っていたので、
  選択はチェックボックス列を足す方式にした。クリックに両方の意味を持たせると、
  シークのたびに選択が変わって落ち着かないため。
- **時刻の自動配置**(§3.5)。`auto` フラグ方式を採用した。
  「ボタンで一括して時刻を入れるだけ」の案もあったが、**その動作は
  『時刻を確定』ボタン 1 個として自動配置方式の中に含められる**のに対し、逆は作れないため。
  手で触った行の挙動はどちらの方式でも同じなので、手動調整のしやすさは損なわれない。

### 当初からの決定
- ファイル名: **タイムスタンプ付き**で常に新規作成(上書き確認なし・連番なし)
- フォント: **Noto Sans JP を同梱**(OFL 1.1)。既定 weight 600、システムフォントにも切替可
- コメント層のみの書き出し: **モードB として MVP に含める**。既定は MOV / qtrle

## 13. 2 つのバックエンド

UI と描画は 1 つのまま、**動画の読み込みと書き出しだけ**を差し替えられるようにした。
`config.js` `parser.js` `layout.js` `renderer.js` `autotime.js` `table.js` はサーバーに依存しないので、
そのまま両方で使い回せる。

```
web/backend/local.js    Node + ffmpeg 経由。ProRes の入出力ができる
web/backend/browser.js  mediabunny(WebCodecs)。サーバー不要 = URL で配れる
```

起動時に `/api/info` が返るかどうかで自動的に選ぶ。

| | ローカル版 | ブラウザ版 |
|---|---|---|
| 起動 | `npm start` | 静的ホスティングに置くだけ |
| 必要なもの | Node + ffmpeg | 対応ブラウザだけ |
| 入力 | **なんでも**(ProRes も。プロキシを自動生成) | ブラウザがデコードできるものだけ |
| 合成 mp4 | ○ | ○ |
| コメントだけ(背景色つき mp4) | ○ | ○ |
| コメントだけ(背景透過) | ○ MOV / ProRes / 連番PNG | × |
| 保存先 | `output/` に直接 + Finder で表示 | ブラウザのダウンロード |

### 13.1 速度(実測)

同じ Mac、`renderer.js` は共通。

| 方式 | 尺 | 所要 | 実時間比 |
|---|---|---|---|
| ローカル(ffmpeg libx264 preset medium) | 720p 12秒 | 約 6 秒 | 0.50x |
| **ブラウザ(WebCodecs)** | 720p 20秒 | **6.7 秒** | **0.34x** |
| **ブラウザ(WebCodecs)** | 1080p 30秒 | **5.9 秒** | **0.20x** |

内訳は `デコード 0.0s / 描画 0.2s / エンコード 5.2s`。
**ハードウェアエンコーダの速度でほぼ決まっていて、解像度を上げてもほとんど変わらない。**

ブラウザ版のほうが速いのは、WebCodecs がハードウェアエンコーダを使うのに対し、
ローカル版は libx264 のソフトウェアエンコードだから。

### 13.2 ブラウザ版の制約

- **対応ブラウザ** — WebCodecs の H.264 エンコードが要る。Chrome / Edge / Safari 17+。Firefox は不可
- **入力形式** — ブラウザがデコードできるものだけ。ProRes の mov は読めない
- **背景透過の書き出しができない** — 代わりに**背景色を選んで mp4** にする
- **メモリ** — 出力を一度メモリに載せる。長尺は `StreamTarget` に替えれば回避できる

### 13.3 なぜ ffmpeg.wasm ではないか

ffmpeg.wasm はマルチスレッドに `SharedArrayBuffer` が要り、そのために
COOP / COEP ヘッダを立てる必要がある。**GitHub Pages はヘッダを設定できない**ので、
サービスワーカーで回避する小細工が要る。

WebCodecs は `SharedArrayBuffer` を使わないので、**ヘッダの設定なしにどこにでも置ける**。
しかもネイティブのハードウェアエンコーダを叩くので速い。

### 13.4 静的ホスティングに置く

`web/` をそのまま上げるだけ。ビルド工程は無い(素の ES モジュール)。
`server/` `samples/` `output/` は不要。

手元で同じ状態を確かめるには `npm run web`(API を持たない静的サーバー)。
